# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A GitHub Pages personal site (`chesunrry.github.io`) — a Korean-language portfolio for **LEE SUNAH** (웹 · 그래픽 디자이너) linking out to Behance galleries.

The entire site is one 5 MB `index.html`. There is no `package.json`, no build step, no tests, and no linter. Pushing to `main` deploys.

Local preview:

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

`file://` also works — the bundler runtime explicitly handles opaque/null origins.

## Architecture: index.html is a bundle, not a page

`index.html` was **generated by the Claude Design canvas bundler**. Do not hand-edit it as if it were markup — the visible page does not exist in the file as HTML. The file is 384 lines with this fixed shape:

| Lines | Contents |
|---|---|
| 1–25 | Static shell: loading badge, "LS" SVG thumbnail placeholder |
| ~26–368 | Inline **bundler runtime** — decodes the manifest, mints `blob:`/`data:` URLs, substitutes UUIDs into the template, swaps `document.documentElement`, re-creates every `<script>` so it executes |
| 370 | `<script type="__bundler/manifest">` — 4.7 MB JSON, **401 assets keyed by UUID** (gzip+base64) |
| 374 | `<script type="__bundler/ext_resources">` — maps CDN URLs → manifest UUIDs (React 18.3.1 + ReactDOM 18.3.1 UMD) |
| 378 | `<script type="__bundler/page_order">` — `[]`; no nested page bundles here |
| **382** | `<script type="__bundler/template">` — **a JSON-encoded string holding the real page.** This is the only line worth editing. |

Manifest contents: 397 woff2 subsets (Barlow, Barlow Condensed, IBM Plex Sans KR), React, ReactDOM, the generated `dc-runtime` bundle, and a near-empty `@ds-bundle` namespace stub.

Assets are referenced inside the template by **bare UUID** (`<script src="cc3fad90-…">`, `src: url("6a67e922-…")`). The runtime rewrites those at load time. Never "fix" a UUID reference into a real path.

### Editing the template

Extract, edit, re-inject — the encoding round-trips byte-identically only with these exact `json.dumps` flags. The `</` → `<\u002F` escape is load-bearing: without it the embedded string terminates the outer `<script>` tag.

```python
import json

P = 'index.html'
lines = open(P, encoding='utf-8').read().split('\n')
i = next(n for n, l in enumerate(lines) if '__bundler/template' in l) + 1

tmpl = json.loads(lines[i])
# ... edit tmpl (a plain HTML string) ...
lines[i] = json.dumps(tmpl, ensure_ascii=False).replace('</', '<\\u002F')
open(P, 'w', encoding='utf-8').write('\n'.join(lines))
```

Verify by reloading the page: the runtime paints a red `[bundle] …` panel bottom-left on any unpack or script error, and swaps the loading badge to `Error unpacking: …`.

## Architecture: inside the template

The template is a `<x-dc>` document rendered by `dc-runtime` (a React-backed template engine, not JSX). Three parts:

**1. `<helmet>`** — everything destined for `<head>`. Holds the ~220 KB of `@font-face` blocks (each pointing at a manifest UUID) and the **"Industry" design-system stylesheet**, which is the source of truth for the look: `--color-*` tokens with 9-step OKLCH-derived tonal ramps, `--font-heading`/`--font-body`, `--space-*`, `--radius-*`, `--shadow-*`, plus component classes (`.nav`, `.btn`, `.blueprint`, `.duotone`, `.halftone`). Retune colors and type there, not in inline styles.

**2. Markup** — declarative directives, all resolved by `dc-runtime`:
- `{{ expr }}` interpolation, bound to keys returned by `renderVals()`
- `<sc-for list="{{ shown }}" as="p">` for iteration
- `sc-camel-on-click`, `sc-camel-on-mouse-enter`, `sc-camel-on-focus`, … for handlers (camelCase props expressed in kebab attributes)
- `style-hover="…"` for hover styles alongside `style="…"`
- `data-reveal="1"` opts an element into the IntersectionObserver scroll-in animation

Sections are `nav` → hero → `#work` (filterable masonry via CSS `columns`) → `#info` (contact) → footer.

**3. `<script type="text/x-dc" data-dc-script data-props="…">`** — the logic, a `class Component extends DCLogic` with `state`, `componentDidMount`/`componentDidUpdate`, and **`renderVals()`**, which returns the object the `{{ }}` bindings read. This is the standard shape: compute everything (labels, counts, colors, handler closures) in `renderVals()`, keep the markup dumb.

Notable module-scope data in that script:
- **`PROJECTS`** — the 8 portfolio entries (`title`, `key` of `brand`/`editorial`, `cat`, Behance `img` URL, gallery `url`). **Adding or reordering work means editing this array.** The filter chips derive their labels and counts from it automatically; adding a new `key` also requires a new entry in the `defs` array inside `renderVals()`.
- **`DARK` / `LIGHT`** — CSS custom-property override maps. `applyTheme()` sets/removes them on `document.documentElement` and flips `colorScheme`. Theme is *not* persisted and does not follow `prefers-color-scheme`; it starts light every load.
- `data-props` JSON declares canvas-editor-tunable props: `hoverGray` (boolean, grayscale on card hover) and `gridColumns` (int 2–4). Read via `this.props.*` with `??` defaults — keep those defaults in sync with the JSON.

Project thumbnails are hotlinked from `mir-s3-cdn-cf.behance.net`, so they are **not** in the manifest and require network access at view time.

## Re-exporting from the canvas

Every export from the Claude Design canvas regenerates the static shell (lines 1-25), which wipes the OG/Twitter meta tags. Crawlers do not run JS, so those tags must live in the static shell, not in the template. After each export:

```sh
python3 scripts/apply-meta.py ~/Desktop/index.html
```

It copies the export over `index.html`, re-inserts the meta block after `<title>`, and rewrites the template's `cherry-thumb.png` references to absolute URLs. Idempotent — safe to re-run. It validates all four bundler payloads before and after writing, and warns if `cherry-thumb.png` is missing from the repo root (that file is the OG thumbnail, extracted from the favicon data URI).

Site constants live at the top of the script: `BASE`, `THUMB`, `TITLE`, `DESC`.

## Conventions

- All user-facing copy is Korean; `alt` text and `aria-label`s are Korean too. Keep new copy consistent.
- Korean text renders in IBM Plex Sans KR; Latin in Barlow / Barlow Condensed. Font stacks are always written `'Barlow', 'IBM Plex Sans KR', sans-serif` — preserve that order.
- Colors come from tokens (`var(--color-text)`, `var(--point, #3F6BB8)`, `var(--btn-fill, …)`) with literal fallbacks, so the page still reads if a token is unset. Follow that pattern rather than hardcoding hex.
- Commit messages in this repo are Korean.
